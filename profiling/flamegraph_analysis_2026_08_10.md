## 5. Remaining bottlenecks (ranked)

### P0 - Candidate matrix assembly (~21% + 11% mask)

`_build_rolling_candidate_matrices` / `_signal_mask_matrix` still reindex
per-ticker onto the master calendar. Bool-array fast path helps only when
`idx.equals(master_ix)`.

**Win:** pre-align panel outputs to `master_ix` once, then pure-numpy column fill.
Expect **~10-20%** on this harness.

### P0 - Price panel + FrameCache (~19% + 10%)

`build_price_panel` + 300× `_build_frame_cache`.

**Win:** bulk-build FrameCache from the price panel block (shared `index_i8`).
Expect **~5-10%**.

### P1 - Day loop Python slots (~18% loop, ~8.5% close, ~9% after_exits)

Still per-slot Python every day.

**Win:** skip `after_exits` when book full + no exit; denser active-slot arrays.
Expect **~5-15%** (more on high-turnover strategies).

### P1 - Results assembly + equity (~14% + 10%)

Post-sim cost. For optimize sweeps that only need a scalar, skip full frames.

### P2 - Pine residual (~9%)

Pandas `rolling`/`sma` dispatch inside the AST. 2D block indicators help complex
expressions more than this simple SMA harness.

### P3 - GPU

Still not GPU-shaped. Cost is alignment, pandas dispatch, and Python object loops.

## 6. Note on default lockfile deps

The tree's default resolved stack is currently **pandas 3.0.5 / numpy 2.4.6**.
This run pins **2.3.3 / 2.4.4** deliberately (same as the 08-09 investigation:
pandas 3 was measured at ~27% wall-clock penalty on this engine). Reproducing
without the pin will look slower and is not an apples-to-apples comparison.
